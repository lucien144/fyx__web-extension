# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A browser extension ("Refined Nyx") that enhances the [nyx.cz](https://www.nyx.cz) discussion site via a single content script injected on every `nyx.cz` / `www.nyx.cz` page. Each feature is a self-contained DOM patch that runs at `document_end`. Its only chrome UI is a toolbar popup that globally enables/disables individual features. Built with [WXT](https://wxt.dev), Manifest V3, Chrome-only.

## Commands

```sh
pnpm dev          # WXT dev mode: builds to .output/chrome-mv3-dev/ with HMR/auto-reload (load unpacked once; does not open Chrome)
pnpm build        # production build → .output/chrome-mv3/
pnpm zip          # packaged .zip for the Chrome Web Store → .output/
pnpm compile      # tsc --noEmit typecheck
pnpm lint         # ESLint flat config (lint:fix to autofix)
pnpm format:check # Prettier check (format to write)
pnpm test         # Vitest (test:watch for watch mode)
pnpm pack:local   # zip + tag HEAD with the built manifest's version (local, offline)
```

- Package manager is **pnpm** (not npm/yarn). Node ≥ 24.
- `postinstall` runs `wxt prepare`, which generates `.wxt/` (types, tsconfig base). Both `.wxt/` and `.output/` are git-ignored.
- `@parcel/watcher` needs a native build; it's pre-approved in `pnpm-workspace.yaml` (`allowBuilds`). If a fresh `pnpm install` complains about ignored build scripts, run `pnpm approve-builds --all`.
- Lint/format/test **are** set up: ESLint flat (`eslint.config.js`) + Prettier + Vitest (pure-logic tests, e.g. `src/features/markdown-render.test.ts`). CI runs them (see below).

## Architecture

- **Entry points:** `src/entrypoints/content.ts` (the content script) and `src/entrypoints/popup/` (the toolbar popup). `content.ts` is `defineContentScript({ matches, runAt: 'document_end', async main() })`; `main()` reads the per-feature enabled map (`loadEnabledMap()`), then calls each enabled feature's `init*()`. The two JS-less style features (`context-menu.scss`, `code-highlight.scss`) are imported for their CSS side-effect, scoped under a root class (`fyx__feat--*`) the content script toggles.
- **Feature registry & settings:** `src/lib/features.ts` is the single source of truth listing every toggleable feature (id, label, description) — pure metadata with no implementation, so both the content script and popup import it. `src/lib/settings.ts` reads/writes each feature's flag in `browser.storage.local` under `fyx__feature__<id>`; features are **enabled by default** (only an explicit stored `false` disables one). The popup (`src/entrypoints/popup/`) renders a switch per feature; toggles apply on the next nyx.cz page load.
- **Feature module pattern:** every `src/features/*.ts` exports an `initX()` function and imports its own `.scss` at the top. Modules guard against missing DOM (return early when their target elements aren't on the page), so all features load on every page and no-op where irrelevant. Styles are namespaced with the `fyx__` prefix.
- **Manifest:** generated by WXT from `wxt.config.ts` (name, description, `permissions: ['storage']`, empty `action: {}` so the icon is pinnable) plus the content script's `matches`; WXT auto-registers `src/entrypoints/popup/` as `action.default_popup`. There is **no** static manifest file to edit and **no** background/service worker. Only the `storage` permission is requested — no host_permissions, no `activeTab`. The **manifest `version` is computed at build time** by `buildVersion()` in `wxt.config.ts` as `[year].[day-of-year].[hourminute]` (UTC), overriding `package.json`'s version — never bump it by hand (see Build & release).
- **CSS injection:** default `cssInjectionMode: 'manifest'` — imported SCSS is compiled by Vite/sass and registered in the manifest's `content_scripts[].css`, so it applies to the nyx.cz page DOM directly.

## Conventions specific to this repo

- Features interact with nyx.cz's existing markup by selector (`#message_box`, `ul.m.l1`, `.wci`, `.input-submit[name=send]`, etc.). These selectors are the site's, not ours — treat them as the integration contract and expect breakage if nyx.cz changes its HTML.
- Cross-reload state uses `browser.storage.local` (markdown module stashes `fyx__preview` before a preview reload, then restores + removes it). `storage.session` is intentionally avoided — it's not reachable from a content script without a background worker.
- The markdown feature rewrites the form on submit: it renames the real textarea, injects a hidden input with the original id/name carrying markdown-rendered HTML, so nyx.cz receives rendered content instead of raw text.

## Build & release (Chrome Web Store)

- **Store package:** `pnpm zip` stamps the time-based version into the manifest and writes the upload-ready `.zip` to `.output/` (`<name>-<version>-chrome.zip`). `pnpm build` (unpacked, `.output/chrome-mv3/`) is for local verification, not the store.
- **Version scheme:** `[year].[day-of-year].[hourminute]` in UTC, e.g. `2026.244.830`. Monotonic across hour/day/year, each segment within Chrome's `0–65535` limit — the format the Web Store requires. It is generated per build, so two builds in the same minute collide (relevant for `pack:local` tagging).
- **CI (`.github/workflows/ci.yml`):** runs on `develop` pushes and all PRs — `lint`, `format:check`, `compile`, `test`, `build`. No release.
- **Release (`.github/workflows/release.yml`):** runs on push to **`master`** — same checks, then `pnpm zip`, then publishes a GitHub Release (`v<version>` tag at the commit + attached `.zip`, auto-generated notes). **Uploading the `.zip` to the Chrome Web Store is manual** — nothing auto-publishes to the store.
- **Local packaging:** `pnpm pack:local` = `pnpm zip` + `scripts/tag-release.mjs`, which tags HEAD `v<version>` from the built manifest (refuses a dirty tree, does not push the tag). For offline/manual packaging only; the official release path is the `master` workflow above.

## Notes

- Feature status / roadmap lives in `README.md`. Unfinished features (emoji, add user ID to context menu, load-more ajax) are deliberately out of scope until the modernization pass is done.
- Runtime behaviour on nyx.cz can only be verified manually via `pnpm dev` (build/typecheck passing does not prove the DOM patches still match the live site).
